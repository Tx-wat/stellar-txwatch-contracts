# Migration guide: v0.2 (`AlertConfig.tags`)

This guide covers the breaking change that adds an optional `tags` field to
`AlertConfig` and a trailing `tags` argument to `AlertRegistry::register_alert`.

## What changed

- `AlertConfig` gained `tags: Option<Vec<String>>`. Tags are optional,
  client-side labels (max 10 tags, each max 32 bytes). The contract stores them
  but does not index them.
- `register_alert` gained a trailing argument:

  ```text
  register_alert(owner, target_contract, label, webhook_hash, rules, tags: Option<Vec<String>>)
  ```

  Pass `None` to register an alert without tags.
- New errors: `TooManyTags` (more than 10 tags) and `TagTooLong` (a tag longer
  than 32 bytes).
- `update_tags` can change tags on an existing alert.

## Updating TypeScript callers

1. Regenerate the TypeScript bindings from the new contract build (see
   `bindings/` and `docs/ISSUE_276_BINDINGS_REGEN_PLAN.md`). Do not hand-edit
   the generated types.
2. Add the new trailing argument to every `register_alert` call. Existing calls
   that omit it will fail to compile against the regenerated bindings and fail
   at runtime against a v0.2 contract.

   ```ts
   // before
   await client.register_alert(owner, target, label, webhookHash, rules);

   // after
   await client.register_alert(owner, target, label, webhookHash, rules, undefined);
   // or, with tags
   await client.register_alert(owner, target, label, webhookHash, rules, ["prod", "dex"]);
   ```

3. If your code reads `AlertConfig` objects, treat `tags` as possibly absent.
   Handle `undefined`/`None` explicitly rather than assuming an array.

## Existing on-chain data

No manual data migration is needed. The new field is an `Option`, so entries
stored before the upgrade deserialise with `tags = None`. Existing alerts keep
working without any write. Call `update_tags` only if you want to add tags to
an existing alert.

## Checklist

- [ ] Bindings regenerated from the v0.2 build.
- [ ] Every `register_alert` call passes the sixth argument.
- [ ] Readers of `AlertConfig` handle `tags` being `None`.
- [ ] Tag inputs respect the limits: 10 tags, 32 bytes each.
